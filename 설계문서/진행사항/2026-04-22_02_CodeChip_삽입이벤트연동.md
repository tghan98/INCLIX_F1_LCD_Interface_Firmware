# 2026-04-22_02_CodeChip_삽입이벤트연동

## 1. 작업 목적
현재 분석 시작 흐름은 STANDBY에서 버튼 입력으로 WAIT_CODECHIP 상태까지 진입할 수 있으나, 코드칩 준비 완료를 실제 하드웨어 이벤트로 반영하는 경로가 아직 없다. 이로 인해 검사 절차 의미가 약해지고, 향후 확장 시 ScreenManager 또는 PowerManager에 검사 의미가 다시 섞일 가능성이 있다. 이번 단계는 코드칩 준비 완료 조건을 Micro SD card 실제 삽입 감지 이벤트로 연결해, WAIT_CODECHIP 이후 흐름이 실제 하드웨어 입력 기반으로 WAIT_CASSETTE까지 진행되도록 최소 구조를 정리하는 것을 목표로 한다.
현재 브랜치에는 SequenceManager 최소 상태와 ScreenManager 조합 기반 장면 선택 구조가 이미 반영되어 있다. 다만 코드칩 준비 완료를 실제 삽입 감지 이벤트로 전이시키는 경로가 아직 없어, 이번 단계에서 해당 간극을 최소 범위로 보완한다.

## 2. 수행내용
### 2.1 CodeChip_Interface 원시 이벤트 연동
CodeChip_Interface가 Micro SD card 삽입/제거 원시 이벤트를 생산하도록 연동한다. 원시 감지 경로는 기존 이벤트 폴링 구조와 동일한 패턴을 따르며, 삽입 에지 검출과 디바운스 처리로 중복 이벤트와 오동작 가능성을 줄인다. 이번 단계에서 CodeChip_Interface의 책임은 원시 이벤트 생산으로 제한하며, SD 파일 접근, lot 파싱, 검증 결과 판단은 후속 단계로 분리한다.

**영향 파일 (신규 생성):**
- `USER/App/CodeChip_App/CodeChip_Interface.h`
- `USER/App/CodeChip_App/CodeChip_Interface.c`
- `USER/Drive/CodeChip_Drv/CodeChip_Drv.h` — 보드 의존 GPIO 핀 정의
- `USER/Drive/CodeChip_Drv/CodeChip_Drv.c` — GPIO 폴링 및 디바운스 구현

**공개 함수 계약 (Button_Interface 동일 패턴):**
- `CodeChip_Interface_Init()` — 드라이버 및 이벤트 버퍼 초기화
- `CodeChip_Interface_Run()` — GPIO 폴링, 에지 감지, 디바운스 처리
- `CodeChip_Interface_GetEvent()` — 미처리 이벤트 1건 반환
- `CodeChip_Interface_GetEventCount()` — 미처리 이벤트 개수 반환

### 2.2 InputInterpreter 변환/전달 연동
InputInterpreter는 CodeChip_Interface가 생산한 원시 이벤트를 CODECHIP_READY 명령으로 변환해 SequenceManager로 전달한다. 이를 통해 버튼 기반 가짜 전이에서 벗어나 실제 하드웨어 이벤트가 검사 절차 전이에 반영되도록 연결한다. 책임 경계는 원시 이벤트 생산(CodeChip_Interface), 변환/전달(InputInterpreter), 상태 전이(SequenceManager)로 고정한다.
이번 단계에서는 제거 이벤트를 상태 전이 트리거로 사용하지 않으며, 원시 이벤트 수준에서만 감지하거나 무시하고 SequenceManager 명령으로 변환하지 않는다.

**영향 파일 (기존 수정):**
- `USER/App/InputInterpreter_App/InputInterpreter_App.h` — `InputInterpreter_Command_t`에 `INPUTINTERPRETER_CMD_CODECHIP_READY` 추가
- `USER/App/InputInterpreter_App/InputInterpreter_App.c` — 이벤트 폴링 루프 수정

**수정 포인트:**
- `InputInterpreter_App_Run()` — `CodeChip_Interface_Run()` 호출 추가, `CodeChip_Interface_GetEvent()` 기반 이벤트 수신 루프 추가
- 이벤트 분기 — 삽입 이벤트 → `INPUTINTERPRETER_CMD_CODECHIP_READY` 변환 후 `SequenceManager_App_SubmitCommand()` 호출

### 2.3 SequenceManager 최소 전이 반영
이번 단계에서는 SequenceManager 상태 축을 불필요하게 확장하지 않고, WAIT_CODECHIP에서 CODECHIP_READY를 수신하면 WAIT_CASSETTE로 전이하는 최소 흐름만 우선 반영한다. SequenceManager는 상태 전이만 담당하도록 유지하며 SD 읽기, lot 파싱, 결과 계산 로직은 포함하지 않는다. 현재는 LOT_VALID를 생산할 실제 모듈이나 검증 producer가 아직 없으므로 VALIDATE_LOT는 이번 단계에 도입하지 않고, 관련 상태/명령은 후속 단계로 분리한다.

**영향 파일 (수정 불필요):**
- `USER/App/SequenceManager_App/SequenceManager_App.h` — `CODECHIP_READY` 명령과 `WAIT_CODECHIP`, `WAIT_CASSETTE` 상태 이미 정의됨
- `USER/App/SequenceManager_App/SequenceManager_App.c` — `WAIT_CODECHIP` → `WAIT_CASSETTE` 전이 로직 이미 구현됨, `SequenceManager_App_SubmitCommand()` 인터페이스 이미 존재

### 2.4 ScreenManager 장면 반영
ScreenManager의 장면 선택 로직에 WAIT_CODECHIP, WAIT_CASSETTE를 반영한다. 전원 축 우선 정책은 기존과 동일하게 유지하고, 표시 가능 전원 상태에서만 SequenceManager 상태에 따라 해당 장면이 선택되도록 구성한다. 이 방식으로 화면 owner는 ScreenManager로 유지하면서도 검사 상태 owner는 SequenceManager로 분리된 구조를 지속한다.

**영향 파일 (기존 수정):**
- `USER/App/ScreenManager_App/ScreenManager_App.c` — 장면 매핑 및 display scene 판단 로직 수정

**수정 포인트:**
- `ScreenManager_ResolveState()` — `SequenceManager_State == WAIT_CODECHIP`, `WAIT_CASSETTE` 분기 추가
- `ScreenManager_IsDisplayScene()` — `WAIT_CODECHIP`, `WAIT_CASSETTE` 장면을 display-capable로 추가

### 2.5 통합 검증 시나리오 정리
STANDBY에서 버튼 클릭 후 WAIT_CODECHIP 진입, SD 미삽입 시 대기 유지, SD 삽입 시 WAIT_CASSETTE 전이를 기본 검증 시나리오로 정의한다. 추가로 SLEEP, POWER_OFF_NOTICE, POWER_OFF가 검사 장면보다 우선되는지와 BAT LOW overlay 회귀 여부를 함께 확인해 기존 정책 영향도를 점검한다.

## 3. 성공 기준
- STANDBY에서 버튼 입력 시 WAIT_CODECHIP 진입 여부를 확인한다.
- SD 미삽입 상태에서 WAIT_CODECHIP 유지 여부를 확인한다.
- SD 삽입 감지 시 CODECHIP_READY 기반으로 WAIT_CASSETTE 전이 여부를 확인한다.
- WAIT_CODECHIP 장면과 WAIT_CASSETTE 장면이 실제로 표시되는지 확인한다.
- SD 삽입 에지에서 CODECHIP_READY 명령이 1회 발생하고 중복 전이가 없는지 확인한다.
