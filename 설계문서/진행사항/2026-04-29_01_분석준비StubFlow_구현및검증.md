# 2026-04-29_01_분석준비StubFlow_구현및검증

## 1. 작업 목적
분석 준비 단계의 Stub 기반 흐름을 실제 코드에 반영하고, CodeChip 및 Cassette 실물 제약이 있는 상태에서 READY_TO_INCUBATE(PRESS START)까지의 사용자 흐름이 정상적으로 동작하는지 검증한다.

## 2. 수행내용

### 2.1 SequenceManager 상태 및 명령 확장
기존 WAIT_CODECHIP 이후 바로 WAIT_CASSETTE로 넘어가던 흐름 사이에 VALIDATE_LOT 상태를 추가하고, WAIT_CASSETTE 이후 READY_TO_INCUBATE 상태를 추가하였다. 또한 CODECHIP_INSERTED, LOT_VALID, LOT_INVALID, LOT_READ_FAIL, CASSETTE_INSERTED 명령을 도입하여 물리 삽입과 Lot 검증 결과를 분리하였다.

### 2.2 LotValidator Stub 추가 및 1회 처리 정책 반영
CodeChip_LotValidator Stub를 추가하고, VALIDATE_LOT 상태에서는 SequenceManager_App_Run() 실행 흐름에서 Stub 결과를 1회만 처리하도록 구성하였다. 상태 진입 시점에 1회 처리 플래그를 리셋하도록 하여 동일 상태 체류 중 반복 검증을 방지하고, 이후 실제 CodeChip read/parse 도입 시 교체 가능한 구조를 유지하였다.

### 2.3 InputInterpreter 기반 Cassette Stub 연결
Cassette 실물이 없는 현재 단계 제약을 반영하여 WAIT_CASSETTE 상태에서 버튼 클릭을 CASSETTE_INSERTED Stub 이벤트로 해석하도록 연결하였다. READY_TO_INCUBATE 상태에서는 START_REQUEST를 분석 전이로 처리하지 않고, Power USER_ACTIVITY만 유지하도록 구성하였다.

### 2.4 ScreenManager 장면 확장
분석 준비 흐름에 맞춰 CHECKING LOT, PRESS START, LOT ERROR 화면을 추가하였다. ERROR 화면은 이번 단계에서 세부 원인을 구분하지 않고 단일 LOT ERROR 문구로 유지하였다.

### 2.5 IAR 프로젝트 반영
신규 추가된 CodeChip_LotValidator.c가 실제 빌드 대상에 포함되도록 IAR 프로젝트(.ewp)에 파일을 반영하였다.

## 3. 검증 결과
- [x] IAR 빌드 1회 정상 완료
- [x] STANDBY -> INSERT CODECHIP -> CHECKING LOT -> INSERT CASSETTE -> PRESS START 화면 흐름 확인
- [x] 기존 CODECHIP_READY / CASSETTE_READY 명령명 잔존 없음 확인
- [x] VALIDATE_LOT 상태에서 Stub 결과 1회 처리 구조 반영 확인
