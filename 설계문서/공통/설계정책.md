# INCLIX F-1 설계정책

본 문서는 펌웨어 구조 설계 시 따르는 핵심 원칙을 정리한다.

## 1. 한스텝 상태머신 + 실행 예산
각 모듈은 한 번 호출될 때 1스텝 또는 제한된 건수만 처리하고 return 한다.
한 호출에서 과도한 while 소비를 피하기 위해 최대 처리 건수 또는 시간 예산을 둔다.

## 2. 계층 분리 + 의존 경계
구조는 main -> UserMain -> App -> Driver 순으로 분리한다.
App은 가능하면 Interface를 통해 하위 계층에 접근하고 Driver 내부 디테일 의존을 최소화한다.

## 3. 이벤트/명령 큐 + 예외 기준
상태 전이 유발 입력은 큐 기반 전달을 우선한다.
단순 조회 또는 즉시 응답성 경로는 제한적으로 직접 호출을 허용하되 기준을 문서화한다.

## 4. ISR 최소화
ISR에서는 플래그 세트, 버퍼 푸시, 타임스탬프 기록 등 최소 작업만 수행한다.
파싱, 정책 판단, 디스플레이 갱신은 ISR 밖에서 처리한다.

## 5. 비블로킹 설계
delay와 긴 polling을 최소화한다.
tick 비교, timeout, 상태 전이로 흐름을 구성한다.

## 6. 상태 + 이벤트 기반 전이
상태 전이는 현재 상태, 입력 이벤트, timeout 조건으로 결정한다.
자동 전이와 수동 전이를 분리해 가독성과 디버깅성을 높인다.

## 7. 책임 분산형 정책 조정
정책 조정 계층은 라우팅과 우선순위 결정만 수행한다.
Power, Screen, Analysis의 도메인 정책 실행은 각 매니저가 담당한다.

## 8. 관찰성/복구 준비도
리셋 원인, 큐 오버플로, timeout 발생을 최소 로그로 남긴다.
부팅 시 로그 확인 -> 안전 상태 진입 -> 단계적 복구 순서를 표준화한다.
