# 코드설명 답변 템플릿 (고정 출력형)

적용범위:
- 코드 설명 요청 시 항상 본 템플릿을 따른다.
- 예외 없이 아래 출력 형식과 문구 규칙을 지킨다.
- 답변 품질 보정이 필요할 때 Add Context로 수동 적용

출력 순서(고정):
1. 구현 순서
2. 코드 블록들
3. 블록별 메타 설명

형식 규칙:
- 답변 시작은 반드시 `구현 순서:`로 시작한다.
- 구현 순서는 반드시 번호 목록(1. 2. 3.)으로 작성한다.
- 코드 블록은 구현 순서 번호와 동일한 순서로 배치한다.
- 각 코드 블록 제목은 반드시 `[N단계] (단계명)` 형식을 사용한다.
- 코드 블록 내부 주석은 반드시 `// 1)`, `// 2)` 형식을 사용한다.
- 주석은 코드 오른쪽이 아니라 코드 줄 위에 작성한다.
- 각 코드 블록 아래에는 반드시 아래 3줄을 이 순서대로 작성한다.

코드위치: (파일명 또는 함수명)
설명: (무엇을 하는지 + 구현 순서 몇 단계인지, 초보자도 이해할 수 있도록)
설계의도: (이 방식을 선택한 이유 — 어떤 문제를 해결하기 위해, 왜 다른 방식 대신 이 방식이어야 했는지)

내용 규칙:
- 코드 발췌는 해당 단계 핵심만 포함한다(불필요한 주변 코드 제외).
- 상태 전이, 플래그, 큐 처리, 예외 처리 중 무엇을 다루는지 명확히 쓴다.
- `설계의도`에서 왜 이렇게 설계했는가가 드러나지 않으면 답변이 불완전한 것으로 간주한다.

금지 규칙:
- 구현 순서 없이 코드부터 바로 제시 금지
- 코드블록별 `코드위치/설명/설계의도` 누락 금지
- `설계의도`에서 "좋다/나쁘다" 수준의 모호한 표현만 쓰는 것 금지
- 단계 번호와 코드 순서 불일치 금지
